# Dockside v0.1.0-alpha.3

This alpha improves scheduled automation, scheduled-backup identification,
the panel updater experience, and fleet-card readability.

> [!CAUTION]
> Dockside remains early-development software and is not recommended for
> production use. Maintain independent backups. The project contributors and
> copyright holders are not liable for data loss, downtime, security incidents,
> or other damages.

## Highlights

- Create schedules from a focused modal and edit every existing schedule,
  including its cron expression, timezone, enabled state, ordered tasks,
  backup file selection, and retention.
- Scheduled backups use the configured name as a prefix and append the run's
  date, time, and schedule timezone. Each run remains a separate UUID-backed
  archive and expires according to its own retention setting.
- Panel Settings displays the installed version without a GitHub request.
  Release checks are manual, development builds return immediately, and only
  active updates are polled.
- The panel updater has been moved below Discord credentials and reduced to the
  essential version, check, release, update, and active-operation controls.
- Server cards are wider on desktop, and the Console command task selector is
  no longer clipped.

## Upgrade from v0.1.0-alpha.2

After this release and its exact-version container images are public:

1. Maintain an independent backup outside the Dockside host.
2. Sign in as the installation owner.
3. Open **Panel settings → Panel version & updates**.
4. Enable prereleases under **Update channel** and select **Check for updates**.
5. Review the release, start the update, and do not interrupt Docker or power
   off the host while the recovery snapshot and rollout run.
6. Confirm the panel reports `0.1.0-alpha.3`, then test one disposable schedule
   and backup before relying on normal automation.

There is no database migration in this release. The updater still creates and
retains one full pre-update recovery snapshot before replacing release-managed
files or exact-version container tags.

## Fresh installation

Download `dockside-game-panel-0.1.0-alpha.3.zip` on Windows or
`dockside-game-panel-0.1.0-alpha.3.tar.gz` on Linux from this release. Do not
use GitHub's automatically generated source archive.

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

Linux:

```bash
chmod +x scripts/*.sh
./scripts/install.sh
```

The guided installer requires a Discord application client ID and client
secret and prints the exact callback URI and one-time owner bootstrap token.

## Known limitations

- Dockside manages only its local Docker host; remote node agents are outside
  the current architecture.
- Windows support uses Docker Desktop with Linux containers.
- Discord attachment limits apply to backup delivery and Discord is not a
  replacement for independent offsite storage.
- Dockside-native catalog synchronization requires outbound HTTPS. Bundled
  Pelican/Pterodactyl compatibility templates remain available offline.
- Development builds identify themselves as `dev` and must be updated from the
  source checkout instead of the in-panel release updater.

Report problems with the structured issue forms and include sanitized
diagnostics. Never attach `.env`, secret files, tokens, webhook URLs, private
backups, or game-server credentials.
